## Actionable findings

### P2: core post-run binding does not validate existing raw prediction receipts

Location: core/safe_entrypoint.py:35-44. bind_completed checks checkpoint hashes against training receipts, then builds a fresh hash mapping over whatever .npz files currently exist. It does not compare previously recorded held-out hashes in evaluation receipts against those .npz bytes before binding. Consequently, pre-binding raw-file drift could be incorporated into a new VERIFIED_COMPLETE binding. This is a static reachable integrity gap; this review did not mutate an existing output or establish actual corruption.

Minimum action: before binding, root independently verifies every recorded held-out/neutral/diagnostic file hash available in original receipts, validates expected condition/length/seed counts and metrics, and fails on missing or mismatched evidence. Prefer adding that check to the new guard itself. The guard's completeness status is not a substitute for scientific recomputation. Its existing path-containment checks and refusing partial/unbound evidence are appropriate. It also honestly describes its binding as post-run consistency, not an original trusted signature.

### P2: learning safe entrypoint fixes overwrites, not frozen-protocol authentication

Location: learning/safe_run.py:10-25 and learning/run.py:64-68. assert_fresh_output correctly refuses nonempty results/checkpoints or training/selection artifacts, without changing them. It still admits a directory containing a changed protocol.json and mismatched protocol.sha256, then delegates to the legacy runner which checks source hashes but not the protocol digest. This was reproduced in audit/review/guard-fixture without running training. Both learning and core guards refused the same fixture once an evidence file existed.

Minimum action: validate protocol.sha256 against protocol.json before delegating on a new run. Preserve the existing frozen source and fix only the successor entrypoint, or enforce that check externally. This does not invalidate the currently running experiment whose protocol/source digests were already independently verified.

### P2: contradictory parser output is accepted by pipeline but rejected by heading registry

Location: integration/pipeline.py:100-105; memory/api.py:137-140; compare memory/headings.py:52-56. The pipeline and controller accept any result with valid=True even when abstained=True. HeadingRegistry correctly treats either invalid or abstained as unresolved. An injected adapter fixture returning valid=True, abstained=True, and one event produced VERIFIED_PARSED_CONSTRAINTS, rejected_observations=0 and heading_count=0.

Minimum action for reusable adapters: require valid AND NOT abstained at both consumption boundaries, validate one-event cardinality before appending semantic records, and check parser result count against input count rather than relying on zip truncation. Preserve every source observation even when rejected. The current LearnedParser emits mutually consistent flags, so this defect does not change the validity of current pinned-checkpoint results; do not claim the adapter contract is fail-closed for arbitrary parser implementations until fixed. Existing tests cover valid=False but not contradictory flags or truncated parser batches.

### P3: negative-parser challenge does not cover held-out paraphrase families

Location: memory/extractor.py:47-48. Negative examples are i%4==3, necessarily odd; held-out layout examples are even. Every negative test therefore uses seen-layout wording. The measured zero negative false-acceptance rate is a finite familiar-layout rejection result, while novel-layout performance is measured only on positives. reports/memory-report.md already warns that negative construction families are shared with training, but can be more exact about this coupling. Do not infer held-out-layout negation robustness from the negative metric. A future factorial challenge would require its own frozen fresh test set; no current retuning is appropriate.

## Verified mechanics and boundaries

1. **Conditional certification, no oracle repair.** pipeline.py:69-80 checks the learned all-node map using observed constraints and returns the original learned candidate prediction. memory/api.py:167-185 computes graph potentials only for consistency and sums candidate residuals; it never supplies these potentials as the answer. For anchored consistent affine components, a path's error telescopes and is bounded by a sum no larger than this component residual sum. The pipeline keeps VERIFIED_PARSED_CONSTRAINTS and source_faithfulness=UNVERIFIED, plus a numeric safety margin. It therefore does not certify the original sentence meaning. Future source-relative acceptance measurements must retain this distinction.

2. **Actual sequential stopping.** Refinements are called one at a time. Accepted adaptive candidates break the loop, so later neural title rounds are not computed. Existing zero-model tests verify one actual call; raw traces count each call. Fixed adaptive=False mode continues to its declared budget and checks its final candidate. Computation saved is title-round count; the complete current prefix has still been encoded before stopping, and verification, archival writes and replay costs remain. Do not equate saved title rounds with the same fraction of total wall time.

3. **Causal replay with recorded decisions.** The replay path passes actual earlier query budgets, consumes every token once within that replay, refines without appending decoder KV and commits feedback once per query. Fresh independent diagnostic used earlier rounds1/2 and current rounds3: run_from_records exactly matched manually executing the same frozen nonzero feedback model, with six actual refinements and six consumed tokens. An unrelated intervening request did not change the repeated answer. Counts include re-executed earlier queries; they are not falsely reported as persistent-state incremental inference.

4. **Compact view intentionally changes the trajectory.** Compact view reconstructs latest constraints and starts a fresh runtime with one current query. It preserves current observed affine obligations, but it discards previous query refinement/feedback trajectory. It is an explicit alternative memory policy, not an exact replacement for replay's hidden state. Compare accuracy and work empirically. Its source comments correctly distinguish these policies.

5. **Compaction preserves inverse facets and prior raw versions.** Absolute and edge assertions are keyed independently. A downstream absolute observation can coexist with the edge needed to infer its parent. Fresh diagnostic crossed three full compactions, revised that downstream observation, observed stale rejection/reopening, verified the corrected inverse candidate, and checked all previous raw rows byte-semantically unchanged before and after closing/reopening SQLite. Two independent current facets survived. No symbolic answer was inserted into the learned pipeline.

6. **Persistence has an honest trust boundary.** Archive API uses INSERT, chronological task/title versions and canonical content hashes; it exposes no update/delete operation. Original text, learned parsing/provenance, traces and compact snapshots persist. Per-row hashes detect accidental payload drift, not deletion or a privileged rewrite of both payload/hash. reports/memory-report.md correctly disclaims filesystem access control. External frozen manifests remain needed for immutable experiment evidence.

7. **Current compact serving still rereads raw history.** memory/api.py:142-151 reads and verifies the complete history, optionally verifies the stored compact hash, then rebuilds latest constraints. It does not use the saved compact payload as a standalone fast serving source. This is source-preserving reconstruction with measured read overhead; it is not proof of archive-independent compressed reasoning or asymptotic retrieval acceleration. Resident raw-record capacity is bounded, while metadata, vector index, reconstructed buffers and traces are separately unbounded. These limits are already mostly stated and must survive integration reporting.

8. **Title identities and versions remain explicit.** HeadingRegistry deterministically hashes task/entity, creates titles only for observed or referenced entities, keeps independent absolute/edge facets, increments semantic version only on assertion changes, retains old snapshots and typed-link history, and does not create headings for missing queries. Fresh roundtrip replay of its hash-linked history was exact. Learned parser chooses event/roles; registry organization is deterministic, not learned topic discovery. Neural Runtime direct-write versions and registry semantic-change versions are distinct counters; do not equate them in reports.

9. **Retrieval is not silently successful.** applicability filters task/title/child/latest facet after hashed vector search. The pipeline uses exact caller-known title reconstruction, not vector search; therefore learned pipeline success would not validate vector retrieval. Existing engineering evidence reports recall@5=0.0417 and MEASURED_NEGATIVE, with zero coverage explicitly unsuccessful. Retain that separation. SQLite stores vector blobs beside raw records but read()/history() do not depend on vector ranking, so archive access and candidate retrieval remain logically separate even within one database.

10. **Extractor scope and selection are appropriately narrow.** BiGRU learns class and token roles; regex tokenizes and checks copy eligibility without solving constraints. Final epoch and threshold0.65 are fixed, IDs are disjoint across splits, and raw per-example predictions remain available. It is a separate finite-language extractor, not the pinned RLT decoder. The report discloses weak withheld-layout exactness and no unrestricted language claim. Heading measurements use seen layouts and cannot overturn that negative transfer result.
